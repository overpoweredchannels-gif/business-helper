# User meeting issue log

## 11 September — automatic reference recognition

Spreadsheet references (Excel, Excel XML and ODS) now recognize their product-table columns directly, without an external AI key or sending worksheet data to a provider. The detector scans up to ten worksheets and fifty rows per sheet, preserving recognized column order/labels and available widths. Unsupported columns are reported. Fonts and header/footer styling remain editable defaults and are explicitly identified for review; arbitrary spreadsheets are not claimed to be exact copies.

PDF/image recognition now prefers the existing Gemini credentials, following the user's approval to check a configured alternative. The primary model and fallback model are tried within the route time budget. Experiential remains available only when Gemini is not configured. No environment files or global AI routing were changed. The existing Experiential key still returned 401. Real synthetic PNG and PDF invoice recognition both succeeded through Gemini on 11 September, detecting Product, Quantity, Rate and Amount. PNG used gemini-3.1-flash-lite after a transient primary failure; PDF used gemini-flash-latest. Production still requires its own configured GEMINI_API_KEY; local credential success alone does not verify production environment variables.

Recognition refuses incomplete output and responses without a supported table. Users can retry the same uploaded file, see size errors before upload, review the preview and explicitly confirm before saving. Tests: `npx tsx scripts/test-reference-recognition.ts` covers XML, multiple worksheets, unsupported columns, sample-data exclusion, provider fallback, PDF request shape and rejection of unfinished/empty responses. Optional live checks use a synthetic file through TRADEOS_REFERENCE_TEST_FILE, never real customer documents. Existing saved-template and permission regressions remain applicable.

Proposed supported fonts/columns/layout are previewed and must be confirmed, then explicitly saved. Exact reproduction of arbitrary fonts/layouts is not guaranteed; unsupported columns are flagged. Reference recognition uses the server's EXPLABS_API_KEY and gpt-6-astra. Validation: full existing npm test suite completed; production build including TypeScript passed. ## Release state

7 September follow-up audit: the other agent's `c8916af` is on main and its Vercel deployment succeeded. Read-only schema checks confirmed `bonus` exists on both `sales_order_items` and `sales_items`; the Phase 12 migration is installed. The draft service preserves bonus when converting an approved draft into invoice items. Customer/product entry now uses one searchable suggestion field. A remaining keyboard defect was found and fixed: reopening an unchanged selection highlighted the first option, so Enter could silently replace the chosen record. Reopening now highlights the selected ID, while explicit arrows/search still change the selection. Empty results cannot leave a negative highlight index. Regression checks cover these cases. Browser interaction verification for this audit was blocked by the browser tool's local kernel-assets startup error; live employee submission and approval still need user acceptance testing.

Audit validation: the full `npm test` suite, focused ESLint checks and `npm run build` (including TypeScript) passed after the selection fix.

Read-only production stock check for the follow-up: all 10 recently updated sampled products with positive stock matched the sum of their persisted inventory movements. No stock quantities were changed during this investigation.

Meeting follow-up: permitted salesmen may submit sales for any active customer in their own organization, whether assigned or unassigned. Assignment/route displays remain available; invoice approval remains required. Customer selection and price lookup follow the updated rule, with tenant and active-customer checks. Sales, purchase, product and category entry advance with Enter; selecting an option moves focus to the next editable field, and Save stays explicit. Customer search includes name/shop/phone. Inventory quantity, badges and summary counts now share the saved product balance, avoiding false out-of-stock badges from stale/partial loaded movement history. Product imports refresh that history, and customer/product/movement reads paginate fully. An additional discovered bug is fixed: employee-entered sale dates now survive submission and approval. Isolated draft tests cover unassigned acceptance, foreign/inactive denial, pending approval and retained dates; inventory tests cover positive balances with empty/partial history, zero/low stock and pagination. Browser fixtures verified customer → date → payment → new product and category navigation without saving.

Sales employee simplicity and access: Sales now has separate owner-configured invoice, ledger, order, return, report, load-form and invoice-generator grants. Existing Sales grants default to invoice submission plus the employee's own ledger. Owner approval remains required, as confirmed in the meeting. API filters force employee ownership; the Phase 11 restrictive database policies enforce ownership, approval-only invoice writes and owner-only permission edits. The new SQL function was observed in production. Employee invoice product selection now searches name/brand/SKU and carries unit mode and bonus into approval. My Profile, the employee dashboard and the permitted ledger show personal confirmed sales with date/customer/brand filters and separate recent pending submissions. Brand values are line net amounts before invoice-level discount/tax. Permission/RLS/tenant/approval/return tests and browser search, Enter navigation and brand filtering passed.

Staff profile session expiry: reported PGRST303 / JWT expired during Save. The profile update now refreshes the session and retries once only after explicit JWT expiry rejection. Failed renewal preserves the draft and requests sign-in; retries are blocked if the account changes. Regression checks cover recovery, repeat expiry, failed renewal, account switching, missing sessions and permission errors.

Release checks passed: full validation (lint: zero errors, 632 warnings; TypeScript; default test suites), production build, and invoice keyboard browser fixtures. The main-branch push uses the repository's existing Vercel integration; its deployment status is tracked against the release commit. Previously missing inventory quantities have not been changed.
